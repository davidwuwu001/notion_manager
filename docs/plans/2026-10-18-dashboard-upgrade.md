## 1. 目标与成功条件

将 `auuuu4/notion-2api-web` 的管理产品能力迁入现有项目：概览、请求日志、数据分析、模型分布、账号状态、集中设置。保留现有 Go 调用引擎、React 管理容器、Chrome 一键导入，以及三个 API 协议。

完成条件：

1. 六页管理后台使用真实数据，不丢失当前账号、工作区、模型 ID 和接入地址复制功能。
2. 一次外部 API 请求只计一次；内部协议转换、重试、切号可以追溯，但不能冒充多次用户请求。
3. 正式 Business 新增规则覆盖所有新增入口；同邮箱不同工作区不混用身份。
4. 支持N个账号组成动态账号池，不硬编码为2个或5个；新版滚动/月度额度参与选路，限流、额度耗尽、登录失效与临时错误分开处理。
5. 原有 `/v1/messages`、`/v1/chat/completions`、`/v1/responses`、`/v1/models` 和 `127.0.0.1:8081` 保持兼容。
6. 保留原账号文件、配置、管理密码、API Key、旧用量汇总；新增数据能独立回滚。
7. 单元、接口、协议和真实浏览器验收分别通过，之后才能宣称升级可交付。

## 3. 明确采用与不采用的内容

### 采用

- 上游的页面组织、请求筛选/分页/详情、趋势/分布/延迟展示、集中设置交互。
- 现有 React 19 + TypeScript + Tailwind、设计 token、中英文和 Go embed 交付方式。
- 现有账号导入扩展、JSON/token 备用导入、账号身份、三协议转换、模型获取与复制。
- 一个 Go 进程、一份账号池、一套管理登录；不新增 Python/Nginx 伴生后台。

### 不照搬

- 免费号自动注册、额度耗尽自动补号、以注册代替购买 Business。
- 上游的无鉴权管理接口、返回 token_v2 的账号 DTO、Token 前缀展示。
- 用请求次数代替真实额度、用词数代替真实 Token、取各模型 P95 最大值代替全局 P95。
- 先缓存整段正常流再统一输出、流式失败仍无条件记成功的实现。
- 重新写三种协议引擎、强制迁移账号存储、引入通用路由/UI/图表框架。
- 首版增加加权调度、成本路由、多租户计费、云部署和 `/ai` 网页无感切换。

迁移方式不是原样复制六个 HTML 文件。上游 `/api/*` 与本项目 `/admin/*` 的认证和字段不同；选择复用当前 React 容器，迁入产品功能及必要的资产/交互，减少维护两套前端的成本。

## 5. 共享数据合同（P0 冻结后才能并行写代码）

### 5.1 账号与身份

- AccountID必须复用现有 `ComputeAccountID`；其SHA-256输入分隔符是单个NUL字节（0x00），不是反斜杠与数字组成的字符串。不得自行跨语言重算或改成随机ID。
- 会话、日志、尝试明细、池成员资格、冷却及并发占位均使用 AccountID；展示名称/邮箱仅为辅助信息。
- 旧邮箱参数仅在唯一匹配时兼容；多工作区同邮箱返回 409，不能打开、刷新或删除首个匹配项。
- 更新 Token 或删除账号后，关联旧反代/对话会话的有效性必须处理，不能让新请求继续使用已删除或过期对象。

### 5.2 一次请求和多次尝试

一个外部请求产生一个 `request_id`，账号重试产生 `attempt_no`。OpenAI 转 Anthropic 内部桥接必须继承该请求上下文。

请求最小字段：

```text
schema_version, request_id, started_at_ms, finished_at_ms,
protocol, requested_model, resolved_model, stream,
status(in_progress|success|rejected|failed|cancelled|interrupted), http_status,
duration_ms, first_token_ms?, final_account_id?, attempt_count,
input_tokens?, output_tokens?, usage_source(actual|estimated|unknown),
error_code?, safe_error_message?
```

尝试最小字段：

```text
request_id, attempt_no, account_id, started_at_ms, finished_at_ms,
outcome, retry_reason?, cooldown_until_ms?,
response_committed, content_emitted, tool_call_emitted,
input_tokens?, output_tokens?, usage_source
```

尝试内若有主推理及额外搜索等多次上游调用，还需分别保存 reported/estimated 输入与输出、unknown调用数及usage_completeness。每次上游调用结束后只合并其最后累计快照，不能用单一usage_source掩盖混合来源。

- 请求层统计调用次数/成功率/总耗时；尝试层统计切号和失败原因，二者不能混加。
- 首个内容前耗时与请求总耗时分开；流式响应 HTTP 200 不等于完成成功。
- 零 Token 的失败/取消/成功请求仍计请求数；未知用量为 null，不能伪装为零。
- 多次累计 usage 回调不能相加；已消费的失败尝试用量与最终请求结果分开记录。Researcher 现有估算必须明确标为 estimated。
- 一个请求只终结一次；取消、下游写失败、上游流错误和正常结束必须可区分。
- 不保存完整提示词、回复、工具参数/结果、Cookie、Token、认证头和未脱敏上游错误；首版不提供“查看全文”或日志导出正文。

### 5.3 管理 API

下列为拟新增合同，不是现有接口：

| 接口 | 约定 |
|---|---|
| `GET /admin/request-logs` | `from/to/status/model/protocol/account_id/q/limit/cursor`；按时间和ID稳定游标分页；limit默认50、最大200；q仅搜索允许的元信息 |
| `GET /admin/request-logs/{request_id}` | 按 ID 获取请求与尝试轨迹；不存在404，不通过扫描最近2000条实现 |
| `GET /admin/analytics` | 相同筛选时间窗，返回真实请求计数、分桶、模型/账号分布和延迟分位数；明确时区和数据覆盖起点 |
| `GET/PUT /admin/routing` | 全池调度模式、按AccountID的成员启用/暂停、重试预算及有效候选范围；校验后原子保存并读回，不定义主备角色或账号顺序 |

保留 `/admin/stats` 的旧 Token 聚合语义及现有消费者；新数据不强行覆盖旧历史。账号/模型/设置优先复用已有 `/admin/*`，不要为复刻上游另养一套 `/api/*`。

非法时间/筛选条件400；未登录401；歧义身份409。服务端计算全局分位数，不能由前端取模型分位数的最大值。新面板所有统计须显示真实覆盖区间；旧聚合不能反推出历史逐请求日志。

默认时间范围为 `[from,to)`，存储使用UTC毫秒，页面按用户时区显示。响应附带captured_since、retained_from、data_complete、storage_status；成功率为success/已终结请求数，进行中单独计；延迟分位数以同一窗口内成功请求计算，无样本为null。账号筛选匹配尝试但请求去重，不能将多个账号参与数直接相加当全局请求数。

## 6. 持久化与迁移决定

首版推荐 SQLite：标准库 `database/sql` 配一个纯 Go 驱动。理由是需要持久分页、组合筛选、准确聚合和重启恢复，不为零依赖自研 NDJSON 索引/数据库。

- 驱动候选为 `modernc.org/sqlite`；代理只读查询到的 `v1.60.1` 仅是候选，不是已验证的安装决定。其 Go/传递依赖要求需与本项目和发布矩阵一起验证，再锁定通过验证的非撤回版本。
- 不使用 CGO 驱动、sqlite3 命令行或 Python 数据服务替代进程内存储。
- 新库独立放在现有私有运行目录：拟用 `accounts/.request_logs.sqlite`。账号 JSON、config.yaml、旧 `.token_stats.json` 不迁移、不删除。
- 建议WAL、foreign_keys=ON、有界busy_timeout，首版单连接和短事务；不新增异步补写队列或外部缓存服务。
- 实施前先补 `.gitignore`，覆盖 DB/WAL/SHM/测试证据；目录0700、数据库及附属文件0600，不能让运行数据进版本库。
- requests、attempts、schema_version 分表；唯一键约束防重复。写入不持账号池锁，采用有界超时，迁移事务化；日志写入故障不破坏模型响应，但必须显示采集异常，不能静默丢失后展示准确统计。
- 新增日志建议默认保留30天，页面显示生效范围；清理只针对新库中的自身请求记录，不清除旧调试日志、账号或汇总。
- 重启时对没有终态的遗留记录标 interrupted；不冒充失败已完成或成功。
- 开始请求只建一次in_progress，最终在一个幂等事务中写尝试并更新终态；Finalize采用脱离入站取消的短超时。记录器位于三个生成接口最外层、API Key校验前，跳过OPTIONS和模型/健康/管理查询，认证拒绝可记为rejected且不存原始头/body。
- 旧 Token 聚合单独显示“历史汇总”，新请求日志从实际启用时刻计，不能按比例补造旧日志、延迟和成功率。
- 回滚旧二进制时保留新库，旧版本忽略它；不反向转换账号或删库。数据库升级须维护备份与版本检查。
- SQLite使用WAL时不能把单独复制主文件当成一致备份；首版采取停服务并关闭DB后的私有备份，未知高版本或损坏库不自动删除重建。

## 7. 调度与 Business 规则

### 7.1 Business 新增规则

- 所有新增入口核验正式 Business，不只手动表单：JSON/token/扩展导入、环境发现新增、注册完成热加载、旧任务重试都须覆盖。
- 免费号注册和自动补号不迁入；旧注册创建/start/retry 在 Business-only 新增规则下返回明确业务错误；旧历史可保留只读。
- 存量账号不批量删除、不批量清空永久标记；标记 legacy/unverified，只有显式核验后更新状态。
- 存量账号是否从旧选路中排除，与新增门槛是两个决定。本升级不凭空核实或踢除旧账号；启用“仅正式Business账号池”前，必须核验候选并展示有效范围。后续通过正式Business核验的新导入账号默认启用并加入池，无需另列后备名单。

### 7.2 多账号池调度（首版确认范围）

所有启用的合格账号都是池成员。4、5个及更多账号使用同一候选过滤和调度逻辑，没有固定的主账号或备用账号。管理页同时展示总成员数、当前可用数、冷却/耗尽/失效/手动暂停数；日志记录实际选择和切换原因。

| 模式 | 行为 |
|---|---|
| quota（默认，余量优先） | 从全池当前可用候选中优先选择真实可用余量更充足的账号；同等条件轮转，避免固定偏向列表首项 |
| round_robin（轮询） | 新会话在全池当前可用候选中轮流分配，跳过暂停、耗尽、冷却、失效及明确不支持目标模型的账号 |

兼容默认：旧配置缺少 routing 时仍使用 quota 名称；新版接入滚动/月度额度后，必须标明评分来源和检查时间。不同额度单位不能直接相加；先排除已确认的窗口/账期限制，再使用可比较的余量比例，同分轮转；未知数据采用明确标识的兼容后备，不冒充余额充足。首版只提供上述两种池策略，不引入primary模式、固定优先级、权重、最低延迟或成本路由。

统一流程：建立全池候选快照 → 过滤成员资格、可用性和模型能力 → 已有会话优先复用仍可用的绑定账号，否则按池策略选择 → 在安全重试边界内改选其它候选 → 准确记录请求终态与尝试轨迹。

- 普通新导入账号通过正式Business核验后加入可用池；手动暂停、删除、失效或额度耗尽时退出当前候选，不能影响其它成员。
- 冷却/额度重置到期后先复核，成功再重新参与调度；手动暂停的账号不会因额度恢复被自动启用。
- 已有会话按AccountID固定当前账号，避免每轮在池内跳转；该账号恢复或其它账号余额上升，不抢走仍有效的已有会话。
- 同一次请求用AccountID排除已尝试成员，不能因账号对象被重新导入而重复尝试；尝试上限由当前候选数量和配置预算共同约束，不硬编码两次或五次。预算耗尽与全池无可用账号须返回不同原因。
- 过滤和占位必须并发安全，防止多个新请求同时选择一个已满并发的账号；每个账号的并发上限独立，不将整个池降成单账号串行。到达全部并发上限时明确返回忙碌状态。
- 保留 `/proxy/start?best=true` 现有“额度最佳”含义，不静默改成“按当前策略”；若增加相应操作需单独命名。Research保留自己的能力/额度过滤。同会话并发须串行或明确拒绝冲突，不能同时修改同一Session。

候选过滤与恢复须统一：正式订阅与 Premium 余额分开；特定模型不可用不要封禁整个账号；未知额度不能被伪装为充足。额度接口失败使用有标识的缓存/未知状态，不等同于零额度或立即恢复。

| 故障类型 | 策略要求 |
|---|---|
| 滚动窗口耗尽 | 等真实重置时间后复核；等待期间跳过 |
| 月度额度耗尽 | 等账期窗口恢复；不能靠短冷却反复试 |
| 短时429 | 优先尊重Retry-After并核实限流类型；短时限流不能标为永久耗尽 |
| 401/登录过期 | 暂停、要求重新导入；不自动重复登录或刷新陌生账号 |
| 403 | 区分权限、政策、登录与防护；不统一视为额度用完或永久封号 |
| 400/无效请求 | 返回请求错误，不遍历账号消耗额度 |
| 404/模型不可用 | 标记对应账号/模型能力，不悄悄换成默认模型 |
| 网络/5xx | 在可重试且未提交内容的边界内有限重试，采用短暂冷却 |
| 下游取消/已输出内容或工具调用 | 不透明重放，不执行第二次工具；记录准确终态 |

“还没输出文字”也不一定安全：上游编辑/上传/内建动作可能已经执行。重试合同还必须包含上游是否已提交及副作用是否未知；未知结果先读回或返回明确中断，不承诺跨账号exactly-once。Context须贯穿普通推理、Research、上传和OpenAI桥接channel，退出/取消路径不泄漏goroutine或并发槽。

`/ai` 网页反代仍为固定会话，不承诺自动把网页、文档或权限迁到另一工作区。包含工作区搜索/页面引用的跨工作区重放边界须在策略验收前确认；未确认时采用不自动跨工作区重放的保守行为，并提示原因。

## 10. 测试和业务验收矩阵

### 自动化

- `go test ./...`；涉及共享状态后对相关模块执行 race 检测；SQLite另做CGO=0构建，不把race构建当发布构建。
- `node --test chrome-extension/import.test.cjs chrome-extension/export.test.cjs web/src/account-import.test.mjs`；新前端纯逻辑测试沿用现有工具，不为简单逻辑新增测试框架。
- `npm --prefix web run build`；Mac前端产物复制到embed目录后Go构建/签名验证。现有Makefile含Windows cmd/xcopy，不能未验证就宣称make build适用Mac。
- CI Go版本与go.mod对齐；验证现有五平台CGO=0矩阵及mac/Linux数据库真实打开。版本/依赖未通过前不能宣称SQLite候选兼容。
- 三协议各测stream/non-stream、错误响应、零Token、工具调用/结果、多轮、取消、桥接只计一次。
- 账号池参数化测试至少覆盖1、2、5、8个成员：余量优先与轮询都使用全池候选，不依赖固定两账号结构或五账号上限。
- 5账号混合状态：一个额度耗尽、一个冷却、一个登录失效、一个手动暂停时，仍能选择第五个；全部不可用时返回可解释原因和已知的最早复核时间，不盲目遍历死循环。
- 运行中新增、暂停、删除、重新导入和恢复均正确更新候选；其它可用账号继续服务；同邮箱不同工作区的状态/额度/并发相互独立。
- 并发请求不会超卖单账号槽位；同一次请求不重复尝试同一AccountID；重试预算耗尽与无可用账号可区分；已有会话不因池内其它账号恢复而迁移。
- 可控假上游错误测试：登录失效；429/403/5xx；research已输出后报quota；写入失败；重启中断恢复；DB只读/磁盘错误；分页/分桶/分位数。
- 精确核算：1个外部请求、2次账号尝试，应为1次请求、2次尝试；失败不能提升成功率；累计usage不重复相加；历史Token不变。

### 真实浏览器

- 普通面板优先Codex内置浏览器；Chrome仅用于真实扩展导入或必要兼容性测试。
- 登录/退出/401、六页hash刷新与前后退、全池summary和搜索分页、空/错/加载状态、设置保存失败保留输入及成功读回。
- Chrome读取账号、精确选工作区、一键导入、成功刷新；试用/Free/未知订阅被拒且不写盘；同一AccountID更新不重复。
- 5个及更多池成员的列表/全池状态/模型能力可见；新增合格账号加入调度、暂停账号退出候选、额度恢复后复核再加入；设置页仅有余量优先与轮询，不展示主备配置。
- 完整workspace ID、公开模型 ID、三协议Base URL/端点逐项复制；剪贴板拒绝有可见错误。
- 日志按条件过滤，旧记录按ID打开；真实窗口数据与手算fixture对照；切页/退出无遗留轮询。
- 未登录HTML/API/日志/错误/截图不得出现凭据；管理页不得扩大监听到公网。
- 实际运行Go嵌入产物验收，不拿Vite/mock页面代替；保存本地脱敏证据，不提交截图/日志/数据库。

真实调用仅用于授权后的少量连通性读回，不为演示自动切号烧尽真实额度。工作区文档/工具有写入影响的验收另核对精确目标和授权。

## 11. 发布、迁移与回滚

1. 当前未提交成果先可恢复地留存；不得用reset/checkout覆盖。只备份确切项目/运行目标，不将凭据复制进仓库。
2. 新表增量创建，旧文件不转换；新页面先通过hash入口验收，默认入口变更最后做。
3. 运行时继续使用现有LaunchAgent、Application Support目录、loopback端口和凭据配置；不改成新Docker/Python部署形态。
4. 失败时停止新版本，原子恢复已验证旧二进制及必要配置；保留账号文件与新日志库，禁止用删除数据“回滚”。
5. 回滚后读回health、旧管理页、账号列表和三协议；报告哪一层恢复，不能把进程启动当业务全部正常。
6. 新版日志不能重放为真实请求；失败/超时的非幂等写入先读回，不自动重复导入、删除或注册。
