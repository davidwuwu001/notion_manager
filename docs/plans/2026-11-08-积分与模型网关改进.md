# 积分与模型网关改进计划

目标：在现有本机 Manager 上完成新版积分、单账号测试、真实工具链验收、流式可靠性，以及账号组/延迟调度/API Key 绑定；保留六个账号、现有密钥、数据及默认路由行为。

## 工作顺序与验收

1. **新版积分**：解析 billing_period 下 resolved 的 auto/flex（数值为零与未知分开），兼容旧协议；保留分源状态和最后成功时间。管理后台展示每项和已知汇总、未知数量，避免将 Basic/Premium 当成新积分；验证重复、缺失、无效、失败后旧缓存、精度和真实账号对照。
2. **单账号模型测试**：新增经管理会话鉴权的单账号、指定模型测试，短请求、禁止跨账号回退和工作区写入；显示成功/失败、耗时、脱敏错误；限制并发、超时及重复请求。隔离夹具先测，再进行授权账号小额真实测试。
3. **工具链验收**：先跑现有协议与工具回归，再在隔离工作区测试 Codex/Claude Code 的读文件、命令、修改、结果回传及多轮。按实际可用客户端分别记录通过、失败、未验证；不扩大权限，不删除用户文件。
4. **流式与诊断**：先通过真实或可复现 fixture 定位缺字、截断、错误终态，再修复有证据的问题；测试增量和最终结果一致、异常中断、工具消息去重、不可重放操作不重试，诊断不泄露凭据和正文。
5. **分组、延迟及密钥绑定**：设计本机持久化分组与受限 Key，原有 Key 默认兼容现有全部账号；Key 指定组时任何路由、重试、会话绑定不得跨组，原密钥不覆盖；延迟策略使用有界样本、冷却与并发限制，并保留原默认策略。管理界面可创建/编辑/撤销组与 Key，秘密仅创建时展示。以单元和端到端回归覆盖隔离、无可用账号、持久化、并发和迁移。

## 交付与约束

- 不覆盖已有账户、配置、日志和未经授权的改动；密钥和 cookie 不进入命令输出、版本库或测试记录。
- 针对每项先写有意义的失败测试再实现，逐项运行相关 Go/前端测试、完整回归、构建和隔离 UI 检查。
- 真实调用可能消耗少量积分；工具操作限制于隔离目录。若客户端不可用则明确未验收，不以模拟代替真实结论。
- 部署前核对现有服务和活动请求、备份现有二进制及配置/数据，构建并验证新版本；部署后核对账号、鉴权、模型、额度和可回滚性。失败时保留现有服务或安全回滚。
- 过程、偏差及尚未验证事项回写 Handoff.md；不自动提交、推送。
